## Part 1 -- Booting: From Power-On to Kernel Entry

Chapter 1 (DONE, commit 4e1097d): "Booting a Multiboot2 Kernel: From Power-On to Kernel Entry" -- the real boot chain from BIOS/UEFI firmware through GRUB to this book's own first C code, in four real steps; why this book does not write its own bootloader (real-mode setup and the protected-mode switch are GRUB's own already-correct, real work); the Multiboot2 header's own exact required fields (magic `0xE85250D6`, `header_length`, a checksum forcing a 32-bit sum of zero, a type-0/size-8 end tag), quoted directly from GNU's own Multiboot2 Specification (https://www.gnu.org/software/grub/manual/multiboot2/multiboot.html) and checked field-by-field against this chapter's own `001_boot.asm`. File 001 (`001_boot.asm`/`001_kmain.c`/`001_linker.ld`): a real Multiboot2-compliant entry stub that sets up a stack before calling into C (no stack exists yet when GRUB hands off control), a linker script placing the kernel at the conventional 1 MiB physical load address with `.multiboot_header` ordered first (spec requires it within the first 32 KiB), and a first `kmain()` that talks directly to the COM1 UART via raw `outb`/`inb` port I/O -- no `printf`, no OS, no heap. Real, honestly-kept `ld` warnings (`missing .note.GNU-stack section`, `LOAD segment with RWX permissions`) surfaced during the real build and are explained rather than silenced: this kernel has no paging yet, so there is no MMU-enforced permission system for those ELF-level flags to actually control regardless of what they claim -- a later chapter revisits this once real paging exists. Real, genuinely booted in QEMU 8.2.2 via a real GRUB-built ISO; QEMU's own `isa-debug-exit` device (`-device isa-debug-exit,iobase=0xf4,iosize=0x04`, written to via I/O port `0xf4`) gives a clean, deterministic exit (`QEMU real exit code: 1`) instead of an external process having to kill a kernel that halts forever -- this book's own first real output, captured via `-serial stdio` and locked byte-for-byte into the page (verified via a block-verifier script; 0 diagram-checker violations after 1 fix, a real shell heredoc `<<` in a bash command block that the checker's stray-`<` rule flagged, restructured to show the file content as its own block instead). 1 file (3 real source files: `.asm`/`.c`/`.ld`), cloud-sandbox-only per the toolchain-availability finding above; `mkdocs build --strict` clean.
