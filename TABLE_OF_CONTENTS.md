## Part 1 -- Booting: From Power-On to Kernel Entry

Chapter 1 (DONE, commit 4e1097d): "Booting a Multiboot2 Kernel: From Power-On to Kernel Entry" -- the real boot chain from BIOS/UEFI firmware through GRUB to this book's own first C code, in four real steps; why this book does not write its own bootloader (real-mode setup and the protected-mode switch are GRUB's own already-correct, real work); the Multiboot2 header's own exact required fields (magic `0xE85250D6`, `header_length`, a checksum forcing a 32-bit sum of zero, a type-0/size-8 end tag), quoted directly from GNU's own Multiboot2 Specification (https://www.gnu.org/software/grub/manual/multiboot2/multiboot.html) and checked field-by-field against this chapter's own `001_boot.asm`. File 001 (`001_boot.asm`/`001_kmain.c`/`001_linker.ld`): a real Multiboot2-compliant entry stub that sets up a stack before calling into C (no stack exists yet when GRUB hands off control), a linker script placing the kernel at the conventional 1 MiB physical load address with `.multiboot_header` ordered first (spec requires it within the first 32 KiB), and a first `kmain()` that talks directly to the COM1 UART via raw `outb`/`inb` port I/O -- no `printf`, no OS, no heap. Real, honestly-kept `ld` warnings (`missing .note.GNU-stack section`, `LOAD segment with RWX permissions`) surfaced during the real build and are explained rather than silenced: this kernel has no paging yet, so there is no MMU-enforced permission system for those ELF-level flags to actually control regardless of what they claim -- a later chapter revisits this once real paging exists. Real, genuinely booted in QEMU 8.2.2 via a real GRUB-built ISO; QEMU's own `isa-debug-exit` device (`-device isa-debug-exit,iobase=0xf4,iosize=0x04`, written to via I/O port `0xf4`) gives a clean, deterministic exit (`QEMU real exit code: 1`) instead of an external process having to kill a kernel that halts forever -- this book's own first real output, captured via `-serial stdio` and locked byte-for-byte into the page (verified via a block-verifier script; 0 diagram-checker violations after 1 fix, a real shell heredoc `<<` in a bash command block that the checker's stray-`<` rule flagged, restructured to show the file content as its own block instead). 1 file (3 real source files: `.asm`/`.c`/`.ld`), cloud-sandbox-only per the toolchain-availability finding above; `mkdocs build --strict` clean.

## Part 2 -- Talking to Hardware: Early Device Drivers

Chapter 2 (DONE, commit 62fd74d): "VGA Text-Mode Output: A Real Screen Driver" -- the first chapter after booting, and the first in a new Part, since talking to hardware devices is a different concern from getting a kernel running at all. The VGA text-mode framebuffer at physical address `0xB8000` (real, cited: OSDev Wiki, "Text mode", https://wiki.osdev.org/Text_mode) is memory-mapped hardware -- an 80x25 grid of 2-byte cells, drawn with ordinary stores, no port I/O needed to draw a character. The attribute byte's real bit layout (foreground colour, a foreground-bright bit, background colour, a blink/bright-background bit) is quoted from the same OSDev page; moving the blinking hardware cursor is the one part of this driver that still needs real port I/O, through the VGA CRT Controller's index/data port pair (`0x3D4`/`0x3D5`, registers `0x0E`/`0x0F`), quoted and cross-checked against the OSDev Wiki's own example code ("Text Mode Cursor", https://wiki.osdev.org/Text_Mode_Cursor). File 002 (`002_boot.asm`/`002_linker.ld`, unchanged in shape from Chapter 1; `002_vga.h` -- this book's first header file; `002_vga.c`; `002_kmain.c`): a real VGA driver (`vga_init`/`vga_set_color`/`vga_putc`/`vga_puts`) plus a `kmain` that writes two lines in two different colours and then deliberately never exits (`qemu_exit` is not called), falling through to the boot stub's own halt loop so a QEMU monitor session connected from outside the running machine has time to inspect it. Real, genuinely booted in QEMU 8.2.2; verified two ways neither prior chapter needed: a live QEMU monitor session (`xp /64xb 0xb8000` for a real physical-memory hex dump, `screendump` for a real VGA screenshot, both captured via a Python script driving QEMU's Unix-socket monitor interface) and a real embedded screenshot (this book's first image asset), converted from QEMU's own `.ppm` output to PNG. The hex dump was decoded programmatically to settle a question the OSDev citation alone did not answer -- which byte of each 16-bit cell is the character and which is the attribute -- confirming the character byte sits at the lower address and the attribute byte matches `vga_entry_color(LIGHT_GREEN, BLACK) = 0x0a` exactly, real empirical verification standing in for a secondary citation that failed to fetch. A genuine `volatile` bug (`vga_buffer` declared as a plain, non-volatile pointer to memory-mapped I/O) was found and fixed before this page was locked -- caught by inspection, not by a failure, since it produced no warnings and no visibly wrong output at `-O0`; the QEMU monitor session and screenshot locked into the page are the post-fix, re-verified rebuild, not the original. 5 real source files (`.asm`/`.ld`/`.h`/`.c`/`.c`), cloud-sandbox-only per the toolchain-availability finding in Chapter 1; `mkdocs build --strict` clean; 0 diagram-checker violations; all code/output blocks verified byte-for-byte against their locked sources.

## Part 3 -- Kernel Infrastructure: Descriptor Tables and Utilities

Chapter 3 (DONE, commit 55d6c75): "A Real GDT and a Kernel printf" -- a new Part, since a CPU descriptor table and a software utility are a different concern from either booting or a hardware device driver. This kernel replaces GRUB's own transient GDT with three descriptors it owns and fully understands: a null descriptor, and flat 4 GiB kernel code/data segments. The segment-descriptor byte layout and the access-byte bit meanings (P, DPL, S, E, DC, RW, A) are quoted directly from the OSDev Wiki ("GDT Tutorial", "Global Descriptor Table"); this chapter's own access bytes (`0x9A` code, `0x92` data) and flags nibble (`0xC`) are derived bit-by-bit from that citation rather than pasted from memory. File 003 (`003_boot.asm`/`003_linker.ld`, unchanged in shape; `003_gdt.h`/`003_gdt.c`; `003_gdt_flush.asm` -- the real far-jump CS reload, cited and explained; `003_serial.h`/`003_serial.c` -- Chapter 2's own deferred refactor, the COM1 driver finally moved into a shared header; `003_printf.h`/`003_printf.c` -- this book's first genuinely reusable utility, a real variadic `kprintf` on freestanding C's own `<stdarg.h>` with no libc, supporting `%d`/`%u`/`%x`/`%c`/`%s`/`%%`; `003_vga.h`/`003_vga.c`, unchanged from Chapter 2). Real, genuinely booted in QEMU 8.2.2; verified two ways -- an exact serial-log capture of a real `kprintf` self-test call (every format specifier decoded correctly) and a real QEMU monitor screendump showing the same text on the actual VGA screen, wrapping correctly at column 80 exactly where the serial log's unwrapped text says it should. Reaching the first `kprintf` call at all -- after `gdt_init()` already ran and reloaded every segment register including a real far jump for CS -- is this chapter's own evidence that the GDT install did not triple-fault the machine. 6 real source files (2 new `.asm`, plus `.h`/`.c` pairs for gdt/serial/printf, `.h`/`.c` for vga unchanged), cloud-sandbox-only per the established toolchain-availability finding; `mkdocs build --strict` clean; 0 diagram-checker violations; all code/output blocks verified byte-for-byte against their locked sources.
